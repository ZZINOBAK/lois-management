# Recruiter Demo Requirements

## 목표

Lois Management 프로젝트에 사용자가 로그인 없이 주요 기능을 둘러볼 수 있는 Demo 페이지를 추가한다.

메인 페이지의 "로이스 구경하기" 버튼을 통해 `/demo/**` 영역으로 진입한다.

## 핵심 요구사항

- 기존 예약/발주/근무시간 기능의 동작에 영향을 주지 않는다.
- 기존 서비스 코드와 UI는 가능한 범위에서 최대한 재사용한다.
- Demo에서는 실제 운영 데이터를 사용하지 않고 Dummy Data만 사용한다.
- Demo에서 발생하는 조회/등록/수정/삭제 작업은 실제 운영 DB에 영향을 주지 않아야 한다.
- `/demo/**` 영역은 로그인 없이 접근 가능해야 한다.
- 기존 UI 스타일과 사용자 흐름을 최대한 재사용한다.
- 주요 기능을 약 3~5분 안에 둘러볼 수 있어야 한다.

## Non-goals

- 기존 DB Schema는 변경하지 않는다.
- 기존 API의 요청/응답 규격을 변경하지 않는다.
- 운영 데이터에 접근하지 않는다.
- Demo 기능을 위해 기존 서비스 구조를 대규모로 리팩터링하지 않는다.
- 새로운 라이브러리나 의존성은 사전 승인 없이 추가하지 않는다.
- 특정 디자인 패턴이나 구현 방식을 사전에 강제하지 않는다.

## 설계 원칙

현재 프로젝트 구조를 분석한 뒤,
기존 코드를 최대한 재사용하면서 실제 운영 데이터와 Demo 데이터를 안전하게 분리할 수 있는 방식을 제안한다.

구현 방식은 특정 패턴을 전제로 하지 않고,
변경 범위, 기존 기능 영향도, 유지보수성, 테스트 가능성을 기준으로 결정한다.
